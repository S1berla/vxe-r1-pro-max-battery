# 项目决策记录

## 已确定

### 目标设备

结论：第一版只支持 VXE Dragonfly R1 Pro Max，以及当前使用的 `PID_F58A` 1K 接收器。

理由：单一型号可以把协议、固件差异和回归验证控制在一个明确范围内。

### 连接方式

结论：只实现 2.4G 接收器模式。

理由：用户当前使用的就是 2.4G，且私有 HID 配置接口已经在该模式下验证。

### 官方驱动策略

结论：最终程序不要求用户打开 ATK HUB 界面；允许 ATK HUB 作为后台程序存在，但托盘程序应尽量独立读取 HID。

理由：用户目标是长期、低干扰地显示电量，而不是依赖每次打开厂商窗口。

补充结论：日常使用建议退出 ATK HUB 客户端，以减少 HID 输入句柄争用；但不要卸载接收器或 HID 驱动，并保持接收器插入、鼠标处于 2.4G 模式。

### UI 形态

结论：Windows 通知区域托盘应用，使用电量图标和百分比，悬停显示详细状态。

理由：比任务栏文字挂件更稳定，兼容 DPI 缩放、任务栏重启和全屏应用。

### 协议

结论：使用 COMPX HID 协议，Report ID `0x08`，依次发送 `0x03`、`0x01`、`0x04`。

理由：已通过官方代码和实机读数双重验证。

### 安全边界

结论：调查和第一版程序只发送读取命令，不发送固件升级、配置写入、恢复出厂或配对写入命令。

理由：避免设备进入升级模式、配置损坏或意外重置。

## 已验证

- 设备身份：`VID_3554 / PID_F58A`
- 产品名：`VXE NordicMouse 1K Dongle`
- 数据集合：`usagePage 0xFF02 / usage 2`
- HID Report ID：`0x08`
- 命令长度：16 字节
- 完整 Output Report：17 字节
- 校验和公式已确认
- 电量、充电状态和电压字段已确认
- 实机读数：95%、放电、6672 mV

## 已确定的实现方案

### 最终桌面技术

结论：使用 C# / .NET Framework 4.8 WinForms 托盘应用，通过 P/Invoke 访问 HID。

当前机器未安装 .NET SDK，但已安装 .NET Framework 4.8 和系统 C# 编译器，因此不需要额外安装工具链。

理由：托盘生命周期、开机启动、单实例、原生图标和资源占用更适合长期后台运行，并且采集层已经用同一套 C# 代码验证编译。

### 采集层

结论：`VxeBatteryReader.ReadOnce()` 作为托盘程序和诊断程序共用的唯一协议入口。

理由：避免托盘层和调试脚本出现两套命令实现，后续修改重试、唤醒和解析逻辑时只需要改一处。

### 托盘显示

结论：采用方案 A，托盘图标使用鼠标轮廓，绿色填充高度随电量变化，不显示具体数字；悬停显示精确状态。

理由：`NotifyIcon` 不能稳定地在图标旁长期显示独立文字；用图形比例表达电量比在 16×16 图标内绘制数字更清晰，也不需要额外的置顶窗口。

### 开机启动

结论：首次运行默认写入当前用户开机启动项，右键菜单提供关闭开关。

理由：用户选择安装后默认开机启动，同时保留自行关闭的入口；使用 `HKCU` 不要求管理员权限。

### 低电量通知

结论：第一版不发送低电量通知。

理由：用户当前只需要持续显示电量，避免额外弹窗打扰；后续可以再增加 20% 和 10% 的可选通知。

## 待定

### 与 ATK HUB 共存

尚需验证两者同时打开同一 HID 设备时的读取行为。

计划：

- 优先允许共享打开。
- 读取超时后短暂退避。
- 连续失败时显示“设备忙碌/休眠”，不显示 0%。

### 刷新频率

当前实现：正常状态每 60 秒读取一次；读取失败后自动缩短重试间隔，连续失败后回到 60 秒。

理由：鼠标电量变化慢，低频轮询可降低资源占用和 HID 争用。

## 决策原则

1. 只支持已经验证的型号和接收器 PID。
2. 协议行为以实机结果为准，不凭命令名猜测。
3. 任何超时都不等同于 0% 电量。
4. 读取失败必须可恢复，不能阻塞托盘退出。
5. 不把厂商二进制或完整 ASAR 内容放入最终项目。
